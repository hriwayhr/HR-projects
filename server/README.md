# HR-метрики на своём сервере (VDS: Selectel, VDSina и т. п.)

Отдельный сервер только для HR-метрик: никак не связан с инфраструктурой компании — ни общей сети,
ни общих учётных записей. Вход — по почте и паролю из «Команды» или корпоративным Яндекс ID, права проверяет сервер,
данные — в SQLite на диске сервера в России.

```
браузер ──HTTPS──▶ Caddy (сертификат Let's Encrypt) ──▶ приложение (Node.js, Docker) ──▶ SQLite (server/data)
                                                              └─ каждую ночь — копия в server/data/backups
```

Код входа и прав тот же, что для Yandex Cloud (`cloud/function`): что проверено там — работает здесь.
Подробно о защите — в `cloud/README.md`, раздел «Как устроено».

## Установка (вход по почте и паролю — `AUTH=password`, по умолчанию)

Нужен только сервер: Ubuntu 24.04, 1 vCPU, 1 ГБ RAM, от 10 ГБ диска, SSH-ключ добавлен при создании.
Домен не обязателен: без него setup.sh берёт бесплатный адрес `1-2-3-4.sslip.io` по IP сервера, HTTPS работает.

```bash
# на своём компьютере, из папки с файлами: программа и данные (версия для ПК «HR-метрики.html»)
scp hr-metrics-selectel.zip HR-метрики.html root@IP_СЕРВЕРА:/opt/
ssh root@IP_СЕРВЕРА 'cd /opt && apt-get install -y unzip && unzip -o hr-metrics-selectel.zip -d hr-metrics && bash hr-metrics/server/setup.sh'
```

Скрипт печатает адрес в конце. Вход — логином (почтой) и паролем из «Команды», как в версии для ПК.

Данные загружаются при первом запуске только в пустую базу и после этого удаляются с диска. Положите в `/opt` одно из:
- **папку `data` локальной версии** (`scp -r data root@IP:/opt/`) — всё как есть, вместе с паролями; закройте программу у всех перед копированием;
- версию для ПК `HR-метрики.html` или копию `hr-*.json` из `data/backups` локальной версии или сервера.
Копия, скачанная кнопкой на странице, паролей не содержит — для переноса не годится.
Со страницы данные на открытом сервере загрузить нельзя. После 10 неверных паролей подряд логин закрыт на 15 минут.

Свой домен: A-запись на IP сервера, затем `HR_DOMAIN=домен.ru bash server/setup.sh` (можно и при первой установке, и позже — данные не трогаются).

## Вход через Яндекс ID (`AUTH=yandex`)

1. **Поддомен** с A-записью на IP сервера — в `.env`: `DOMAIN`, `BASE_URL`.
2. **Приложение в Яндекс ID** — <https://oauth.yandex.ru/client/new> под корпоративным аккаунтом:
   платформа «Веб-сервисы», Redirect URI `https://ПОДДОМЕН/api/callback`, доступ «Доступ к адресу электронной почты».
   В `.env`: `OAUTH_CLIENT_ID`, `OAUTH_CLIENT_SECRET`, `ALLOWED_DOMAINS`, `ADMIN_EMAILS`.
3. `bash server/setup.sh`, войдите почтой из `ADMIN_EMAILS` — вы станете первым администратором.

## Что делает setup.sh

- ставит обновления и включает их автоматическую установку (unattended-upgrades);
- файрвол: снаружи открыты только SSH, 80 и 443; fail2ban блокирует перебор SSH;
- SSH — только по ключу (если ключ на сервере есть);
- файл подкачки 1 ГБ, если его нет; после обновления удаляет старые образы Docker;
- создаёт `server/.env` с правами 600 и случайным ключом подписи сессий;
- запускает два контейнера: приложение (не от root, файловая система только для чтения, без
  привилегий) и Caddy, который сам получает и продлевает HTTPS-сертификат.

## Перенос данных с claude.ai (для AUTH=yandex; при AUTH=password данные берутся из «HR-метрики.html»)

1. На claude.ai: **Настройки → Резервная копия → Скачать резервную копию**.
2. На сервере: **Настройки → Резервная копия → Загрузить копию**, укажите, кто вы в загруженной команде.
3. **Настройки → Команда**: впишите каждому корпоративную почту; тестовую запись (test) — в архив.
4. Удалите файл копии с компьютера — в нём персональные данные.

## Каждый день и раз в месяц

- **Копии.** Каждую ночь — `server/data/backups/hr-ГГГГ-ММ-ДД.json`, хранятся 30 дней
  (`BACKUP_KEEP_DAYS`). Это копии на том же диске: от ошибки защищают, от потери сервера — нет.
  Раз в неделю скачивайте свежую копию в надёжное место (`scp root@IP:/opt/hr-metrics/server/data/backups/hr-*.json .`)
  или настройте в Selectel резервное копирование диска сервера.
- **Обновление кода:** замените файлы проекта и запустите `bash server/setup.sh` — пересоберёт и перезапустит.
- **Журнал:** `cd /opt/hr-metrics/server && docker compose logs --tail 100`.
- **Раз в квартал:** кто имеет доступ к проекту в панели Selectel и SSH-ключи на сервере;
  в «Команде» нет уволенных.

## Если что-то пошло не так

| Признак | Что проверить |
|---|---|
| Сайт не открывается | A-запись указывает на IP сервера; `docker compose ps` — оба контейнера `running` |
| «Не получилось войти» | Redirect URI в Яндекс ID совпадает с `BASE_URL/api/callback` буква в букву |
| «Войдите корпоративной почтой» | `ALLOWED_DOMAINS` — домен почты, без `@` |
| «Вашей почты нет в команде» | почта внесена в «Команде» и человек не в архиве |
| Приложение перезапускается | `docker compose logs app` — чаще всего не заполнен `.env` |
