# Портал новых сотрудников i'way

Прототип пребординг-портала: HR выдаёт новичку персональный доступ, новичок видит
страницу со своей командой, документами и планом адаптации, HR следит за готовностью
пакета документов.

**Опубликованная версия:** https://claude.ai/artifact/JY6fX2C2VFecFyGJrLYLH9

Страница — один самодостаточный HTML-файл: шрифты, логотип и вся логика вшиты внутрь,
внешних запросов нет. Данные (сотрудники, администраторы, справочник отделов) живут
в общей базе артефакта, а не в файле.

---

## Структура

```
src/iway-welcome.html   вся страница: вёрстка, стили, логика, шрифты и логотип в base64
assets/                 исходные PNG логотипа (из них собран base64 в странице)
tools/build_logo.py     пересборка логотипа в фирменные цвета
tools/build_fonts.py    сабсет Fedra Sans Pro → woff2 → base64
tests/                  автотесты на Playwright + эмулятор базы артефакта
```

## Три экрана в одном файле

| Экран | Когда показывается |
|---|---|
| Вход | нет активной сессии; две вкладки — «Сотрудник» и «HR» |
| Панель HR | вход по почте и паролю администратора |
| Кабинет сотрудника | вход по логину/почте и паролю новичка |

В панели HR шесть вкладок, в порядке шапки: «Новый доступ» (открыта по
умолчанию), «Выданные доступы», «Администраторы», «Отделы», «Шаблоны»,
«Страница сотрудника». Имя и «Выйти» стоят в правом верхнем углу — и в панели
HR, и в шапке сотрудника (там правее счётчика готовности); в панели HR вкладки
идут своей строкой под ними (`.tabs{flex-basis:100%}`, чтобы имя не
уезжало под вкладки, когда их становится много). Порядок вкладок и положение
имени проверяются в `flow13.py`.

Письмо-приглашение, оффер и сообщения для чата лежат в `#issuePanels` под
вкладками: их открывают и после создания доступа, и кнопкой из карточки в
списке, поэтому внутри одной вкладки они были бы невидимы при вызове из
другой. Видны они только на «Новом доступе» и «Выданных доступах» — на
справочниках (администраторы, отделы, шаблоны, страница сотрудника) им делать
нечего, и `switchTab` их скрывает. Скрывает, а не закрывает: в письме
одноразовый пароль, который иначе пришлось бы перевыпускать из-за случайного
клика, — при возврате на вкладку письмо на месте с тем же паролем. Закрывается
кнопкой «Закрыть», и пока письмо не отмечено отправленным, она переспрашивает.

Маршрутизация — по хешу: `#admin`, `#code=IW-XXXX` (подставляет логин на экране входа),
`#exit`. Якоря разделов (`#docs`, `#team`, …) маршрут не переключают.

## Палитра

Страница и письмо живут на одной палитре — брендбучной. Раньше страница была
на синем `#0055A4` с лаймовым героем, чего нет ни в брендбуке, ни в логотипе
(в логотипе только `#484E41` и `#009634`), ни в письме.

| Роль | Значение |
|---|---|
| Акцент-графика: чекбоксы, полосы прогресса, фокус | Pantone Hexachrome Green C `#009634` |
| Всё, что несёт текст: кнопки, ссылки, подписи, полоса «Жизнь» | `#007026` |
| Заголовки | `#3A3F34` |
| Основной текст | `#5A6055` |
| Приглушённый текст | `#63715F` |
| Фон плашек и героя | `#E4F1E8`, страницы — `#F3F5F1` / белый |

Затемнённый `#007026` нужен там, где на цвете лежит текст: белая подпись на
чистом Green C даёт 3.88:1 и не проходит AA. На `#007026` — 6.28:1. Сам Green C
остался в графике, где контраст к тексту не предъявляется.

Все текстовые пары проверены на AA (минимум в наборе — 4.72:1). Токены
`--blue*` и `--avo` сохранили имена от прежней синей версии; значения в них
брендовые, переименование не делали, чтобы не раздувать правку.

## Данные

Коллекции в базе артефакта:

```
admins/<email>          { email, name, role, salt, hash, createdAt }
employees/<code>        { code, login, lastName, firstName, gender,
                          dept, email, personalEmail, startDate, startTime,
                          salt, hash, demoPass?, progress, cardChoice,
                          createdAt, openedAt, sentAt, docsSentAt,
                          offer?, offerSentAt?, offerReply?, offerReplyAt?,
                          accessAt? }
config/departments      { list: [{ name, head, senior, chat, intern }] }
config/page             { sections: { <ключ раздела>: { hidden, title, lead,
                                                        items? } } }
config/templates        { tpl: { offer: { subject, title, body },
                                 intern: { first, second } } }
```

- `progress` — именованные ключи документов: `passport`, `snils`, `military`,
  `labor`, `inn`, `diploma`, `ndfl`, плюс `day0…day4` для плана первого дня.
- `firstTime` — ключи документов, которые сотрудник оформляет впервые
  (`{labor: true}`): пункт закрыт ответом, а не отметкой «принесу».
- `cardChoice` — `have` / `need` (карта Альфа-Банка).
- `demoPass` — только у тестовых профилей: пароль зафиксирован и не перевыпускается.
- `sentAt` — когда HR отметил письмо отправленным; `docsSentAt` — когда сотрудник
  нажал «Отправить список в HR».

## Кабинет сотрудника: этапы и шаги

Кабинет — не длинная страница, а панель этапов слева и карточки шагов справа.

| Этап | Когда открывается | Что внутри | id секции |
|---|---|---|---|
| До выхода | всегда | шаги 01–06 (см. ниже) | — |
| 1-й день | дата выхода | дата выхода, обратный отсчёт, чек-лист дня | `plan` |
| Первая неделя | +7 дней | чек-лист: обучение, регламенты, цели на 30/60/90 | `week` |
| Первый месяц | +30 дней | чек-лист: вводный курс, встречи 1:1, сверка на 30 днях | `month` |
| Окончание испытательного срока | дата выхода + срок из оффера | чек-лист: сверка на 60 и 90 днях, учебный центр, тренинг | `prob` |

Панель слева разбита на два блока (`.st-group`): **«Этапы»** — только путь, от
«До выхода» до «Окончания испытательного срока», со сроками под названиями; и
**«Полезная информация»** — справочные вкладки, пока одна:

| Вкладка | Когда открыта | Что внутри | id секции |
|---|---|---|---|
| Контакты | всегда | копия шага 06 без опроса о странице | `helpContacts` |

Срок под названием есть только у этапов пути — в «полезной информации» нечего
датировать, поэтому у таких кнопок `.st-s` в разметке просто нет, а
`renderStages` его наличие проверяет.

Заголовки блоков (`.st-cap`) оформлены как надзаголовки разделов на странице:
зелёная черта и тёмный текст. Сноска под списком этапов сделана мельче и
светлее, а блоки разделены линией — иначе «Полезная информация» читалась вровень
со сноской. `flow19.py` сверяет, что цвет заголовка отличается от цвета сноски,
у заголовка есть черта, а между блоками есть линия.

У всех четырёх этапов пути — чек-листы того же вида, что в первом дне: свои
ключи прогресса (`week0…`, `mon0…`, `prob0…`), свой счётчик «N из M» с полосой.
В **готовность в шапке** они не входят: она по-прежнему считает обязательные
документы плюс отметки первого дня, иначе процент у уже вышедших сотрудников
поехал бы задним числом. `flow19.py` это проверяет.

Вкладка «Контакты» открыта всегда и никогда не становится этапом по умолчанию
(флаг `aside`). Её карточка — копия шага 06: `mirrorContacts()` клонирует
`#contacts .wrap` в `#helpContacts` на каждом `applyPage()`, снимая номер шага,
классы появления и блок опроса о странице (он остаётся только в шаге 06). Так
HR правит контакты в одном месте, а сотрудник видит их на любом этапе.

Срок испытательного берётся из оффера (`rec.offer.probation`, «2 месяца» или
«3 месяца»); не указан или не распознан — считаем стандартные три месяца.
Закрытый этап виден в панели с датой («с 5 октября»), но не открывается:
`switchStage` на нём выходит, кнопка помечена `aria-disabled`.

По умолчанию открывается последний доступный этап: у новичка это «До выхода»,
у вышедшего — его этап.

Содержание закрытых этапов лежит в DOM, просто не показывается, — поэтому
счётчик готовности в шапке считает то же, что и раньше: обязательные документы
плюс отметки первого дня. Каждый этап правится в панели HR отдельной строкой
(«Этап «Первая неделя»» и так далее), свой заголовок, подзаголовок и список.

Срок этапа выводится в карточке строкой `.stage-when`: `.h-date` с
`data-offset` в днях от выхода, а у испытательного — `data-offset="prob"`,
то есть его конец, посчитанный из оффера.

Двух кнопок-заглушек из старого блока адаптации («База знаний», «Записаться на
обучение») больше нет: они вели на `#faq` и `#contacts`, а те живут в другом
этапе — межэтапный якорь никуда не ведёт. Вернём, когда будут реальные ссылки.

Вид списка `plain` (точки без отметок) больше не используется — все списки
этапов стали чек-листами, поэтому его чтение и запись убраны. Остались виды
`faq`, `contacts`, `check`, `values`, `cards`.

### Статьи к прочтению

В шаге «О компании» — список внешних материалов (`#aboutReads`): история
компании, разница такси и трансфера, происхождение апострофа в названии.
Список правится в панели HR тем же механизмом, что контакты (`kind: 'contacts'`,
поля «Рубрика · Название · Ссылка»), поэтому схемы ссылок проходят тот же
разбор: `http/https/mailto/tel` — пускаем, остальное отбрасываем. Внешние
ссылки открываются в новой вкладке с `rel="noopener"`.

Названия статей — описательные, не дословные: домены forbes.ru,
buyingbusinesstravel.com.ru и iwayex.com закрыты сетевой политикой окружения,
проверить заголовки на страницах не удалось. Ссылки сохранены как прислал HR,
названия правятся во вкладке «Страница сотрудника».

### Шаги этапа «До выхода»

| № | Блок | id | Что внутри |
|---|---|---|---|
| — | Приветствие | `hero` | «Добро пожаловать», просьба пройти шаги, дата и время выхода, отдел и руководитель, готовность документов |
| 01 | Анкета | `form` | ссылка на анкету нового сотрудника |
| 02 | О компании | `about` | цифры, миссия, ценности, статьи к прочтению; рядом — «Жизнь в i’way» (`culture`) |
| 03 | Команда | `team` | руководитель, наставник, команда отдела, рабочая почта — из справочника отделов |
| 04 | Что взять с собой | `docs` | чек-лист документов и кнопка «Отправить список в HR» |
| 05 | Дресс-код | `dress` | смарт кэжуал: что подойдёт, чего не надо, первый день, если сомневаешься |
| 06 | Контакты | `contacts` | кому писать; рядом — частые вопросы (`faq`) |

Номера шагов проставляет `renumberSteps()` из `applyPage()`, а не CSS-счётчик:
их видно тестам, и когда HR скрывает шаг, нумерация пересчитывается без дырки.
«Жизнь в i’way» и «Частые вопросы» номера не носят — они дополняют соседний
шаг.

Навигации по разделам больше нет: её место заняла панель этапов, а в шапке
показывается название текущего этапа (`#tbStage`). На экране до 980 px панель
превращается в горизонтальную ленту; `minmax(0,1fr)` и `min-width:0` держат
колонку, иначе страница едет вбок по ширине ленты.

## Движение

Два эффекта, оба выключаются системной настройкой `prefers-reduced-motion`:

- **счётчики** в блоке «О компании» досчитываются при появлении (`data-to`,
  `data-dec`, `data-suffix` на `.fig .n`);
- **мягкое появление блоков** при прокрутке. Наблюдаются контейнеры, а не
  отдельные строки: сетки ценностей и карточек склеены в один блок и
  разъезжаться не должны. Класс `js-reveal` ставит сам скрипт и только после
  того, как страница сотрудника показана — у скрытой ничего не пересекается с
  окном, и блоки остались бы невидимыми. Без скрипта и при reduced-motion всё
  видно сразу.

## Блоки страницы сотрудника

Вкладка «Страница сотрудника» в панели HR: у каждого раздела личной страницы
можно переписать заголовок и подзаголовок и выключить показ. Настройки общие
для всех сотрудников, лежат в `config/page`.

Ключи разделов совпадают с их якорями: `hero`, `team`, `about`, `docs`,
`plan`, `culture`, `faq`, `contacts`. Первый экран скрыть нельзя — у него
правится только подзаголовок.

Блоки разложены по этапам кабинета: слева та же панель этапов (`#pageStages`,
строится из `STAGES` без справочных вкладок), справа — блоки выбранного этапа.
У каждой записи `PAGE_SECTIONS` есть поле `stage`, оно и решает, где блок
показывать. Переключение этапа пересобирает список; несохранённые правки лежат
в `state.page`, поэтому пересбор их не теряет — `flow14.py` это проверяет.
Кнопка «Сохранить страницу» сохраняет правки всех этапов сразу.

В поле сразу лежит текущий текст — как во вкладке «Шаблоны»: его правят с
места, а не набирают заново поверх подсказки. Исходные строки снимаются со
страницы при первой отрисовке (`capturePageDefaults`), остаются подсказкой в
`placeholder` и возвращаются, если поле очистить. В базу попадает только то,
что HR действительно тронул. Скрытый раздел исчезает со страницы, а нумерация
остальных шагов пересчитывается.

Списки внутри разделов тоже правятся: документы (обязательные и нет), план
первого дня, первая неделя, 30/60/90, ценности, карточки «Жизни», вопросы и
контакты. Строку можно переписать, добавить или удалить. Список лежит в
`items` своего раздела; там, где списков несколько, у остальных свои ключи
(`extra` у необязательных документов, `week` и `months` у плана).
Пока HR его не трогал, `items` нет и строки берутся из вёрстки; после первой
правки список отвязывается, а кнопка «Вернуть исходные» его обнуляет. Пустая
строка на странице не показывается, но в редакторе сохраняется — чтобы
недописанная не пропадала.

У контакта три поля: подпись, значение и ссылка. Ссылка необязательна: без
неё значение выводится без перехода, с надписью «Уточняется». Если значение
похоже на почту, `mailto:` подставляется само. Подпись у ссылки берётся из её
схемы — `mailto:` даёт «Написать», `tel:` — «Позвонить», остальное «Открыть».
Пускаем только `http(s):`, `mailto:` и `tel:`: поле правит один человек, а
открывают ссылку все, поэтому чужая схема вроде `javascript:` отбрасывается
и строка показывается без перехода.

Текст HR попадает на страницу через `textContent`: разметка в поле не
исполняется, а выводится как есть.

Отметки сотрудника привязаны к ключу пункта, а не к его порядку: у документов
это `data-key` из вёрстки, у плана первого дня — `day0…day4`. Редактор переносит
ключ существующего пункта как есть, новым выдаёт свой. Поэтому переименование
или перестановка не сбивает уже поставленные галочки, а удаление пункта просто
перестаёт их читать. Признак «только для мужчин» — тот же `data-doc="mil"`,
теперь их может быть несколько.

Нумерация ценностей («Ценность 01») проставляется по порядку сама, первая
карточка «Жизни» всегда выделена цветом — чтобы список нельзя было привести
в несогласованный вид.

Скрытие «Документов» и «Адаптации» уносит чек-листы — сотрудник не сможет
отметить документы и отправить список, а счётчик готовности в шапке замрёт.
Это не запрещено, но в интерфейсе подписано.

## Оффер

Отправляется тем же способом, что приглашение: HR собирает письмо, копирует
его в свою почту и отмечает отправленным. Поля живут в `rec.offer`, отметка —
в `offerSentAt`.

Оффер — шаг **до** доступа: кандидат принял приглашение, но сотрудником ещё не
стал. Поэтому в форме «Новый доступ» есть кнопка «Собрать оффер»: письмо
собирается из полей формы, карточка при этом не создаётся (нужны только
фамилия и имя). Панель помечена «Черновик до создания доступа», отметки
«Отправлено» у неё нет — отмечать нечего, записи ещё нет.

Правки в панели черновика и поля формы — один и тот же объект `state.newOffer`,
поэтому при закрытии панели форма перерисовывается, а при создании доступа
поля уезжают в карточку как есть. Позже оффер открывается кнопкой «Оффер» в
карточке; там правки сохраняются сразу и сразу видны в предпросмотре.

Так же и со стажировкой: у отдела с флажком «Стажировка» вместо блока оффера
появляется кнопка «Собрать приглашение» — первое сообщение можно отправить до
доступа. Второе сообщение несёт ссылку и пароль, поэтому в черновике оно
скрыто с пояснением и появляется после создания доступа.

Порядок абзацев и формулировки задаёт шаблон (вкладка «Шаблоны»), а не код:
сплошной текст, без сведения условий в таблицы. `flow15.py` проверяет этот
порядок на исходном шаблоне отдельно.

Тема письма: `Оффер для Фамилия Имя на позицию «должность», i’way`. Она видна
в подсказке у кнопки «Тема» и проверяется тестом.

Переменные: должность, задачи (каждая строка — отдельный пункт), испытательный
срок, график, часы работы, руководитель, зарплата на испытательном и после,
дата ответа. Пустое поле просто не попадает в письмо: без должности нет абзаца
про должность, без срока ответа — строки про срок.

## Шаблоны писем

Вкладка «Шаблоны»: текст оффера (тема, заголовок, тело) и двух сообщений о
стажировке правятся как обычный текст. Значения из карточки подставляются по
именам в фигурных скобках, вёрстка письма от текста не зависит.

Подстановки оффера: `{имя}` `{фамилия}` `{должность}` `{задачи}`
`{испытательный срок}` `{график}` `{часы работы}`
`{зарплата на испытательном}` `{зарплата после}` `{руководитель}`
`{срок ответа}`.
Подстановки стажировки: `{имя}` `{фамилия}` `{дата выхода}` `{время выхода}`
`{ссылка}` `{логин}` `{пароль}`.

Правила разметки шаблона:

- абзацы разделяются пустой строкой;
- строка, начинающаяся с `- `, становится пунктом списка;
- **строка с пустой подстановкой выпадает целиком** — иначе в письме осталось
  бы «в должности «»» или «до  включительно»;
- `[кусок в квадратных скобках]` необязателен: с пустой подстановкой внутри
  исчезает только он, а строка остаётся. Так `Ждём вас {дата выхода}[ в
  {время выхода}].` не теряет дату, если время не указано;
- блок, от которого осталась одна ведущая строка на «:», не печатается —
  заголовок без списка смысла не имеет.

Значения подставляются выделенными (полужирный, цвет 447 C), многострочные
(задачи) — без выделения. Весь текст экранируется: теги из поля попадут в
письмо буквами, а не разметкой.

Шаблоны разложены по категориям тем же приёмом, что блоки страницы: слева
список категорий (`#tplStages` из `TPL_SECTIONS`, с числом полей), справа —
поля выбранной. Переключение категории пересобирает поля, правки лежат в
`state.templates` и не теряются. Кнопка «Сохранить шаблоны» сохраняет всё
сразу.

В поле сразу лежит текст, который уходит в письмо: его правят с места, а не
набирают заново поверх подсказки. Исходные тексты лежат в `TPL_DEFAULT` в коде;
в базу попадает только то, что HR действительно тронул, а очищенное поле снова
берёт текст из кода. Кнопка «Вернуть исходные» сбрасывает всё сразу и
переспрашивает. Правки лежат в `config/templates` и общие для
всех — как настройки страницы.

## Кандидат → доступ

Между отправленным оффером и доступом к порталу есть промежуточный шаг.
**Кандидат — это та же запись `employees/<code>`, но без пароля**: `hash` и
`login` пустые, поэтому войти по ней нельзя (`checkPassword` без `hash` всегда
возвращает false). Признак — `hasAccess(rec)`.

Путь:

1. HR собирает оффер в форме «Новый доступ» кнопкой «Собрать оффер» — пока это
   черновик, в базе ничего нет.
2. Отправил — жмёт в панели «Отправлен — сохранить кандидата». Появляется
   карточка со статусом «оффер отправлен · ждём ответа», форма очищается.
3. В карточке кандидата — кнопки «Принят» и «Отказ» (`offerReply` = `yes`/`no`,
   дата в `offerReplyAt`; повторный клик снимает отметку).
4. «Создать доступ» выпускает пароль, проставляет `accessAt` и открывает
   письмо-приглашение. Если стоит отказ, кнопка переспрашивает.

Дальше карточка живёт как раньше: письмо, документы, статусы. У стажировки то
же самое, только словом «приглашение» и с сообщениями для чата вместо письма.

Статусы кандидата идут перед обычными: `draft` (не отправлен), `offered`
(ждём ответа), `accepted` (принят — выдать доступ), `declined` (отказ).
В карточке кандидата нет ни чек-листов, ни логина с почтой — их просто ещё не
существует.

## Этапы списка «Выданные доступы»

Этапы вынесены в панель слева — ту же, что в кабинете сотрудника и в
редакторах страницы и шаблонов (`.pg-wrap` + `aside.stages.pg-stages`). Весь
путь виден сразу, у каждого этапа — счётчик людей:

| Группа | Этапы |
|---|---|
| — | Все записи |
| Кандидаты | Оффер не отправлен · Ждут ответа · Оффер принят · Отказались |
| Сотрудники | Отправить письмо · Не заходили · Собирают документы · Собраны, ждут отправки · Список отправлен |
| Отметки | Заявка на карту |

Ключи совпадают со `statusOf`, кроме `card` — это отметка (нужна карта
Альфа-Банка), а не этап, поэтому она стоит отдельной группой. Порядок и
состав панели задаёт `FILTER_GROUPS`; плоский `FILTERS` собирается из него.

Пустой этап из панели не пропадает, а приглушается (`.st.dim`): HR видит, что
на этапе никого нет, а не ищет исчезнувшую строку — раньше чипы фильтров с
нулём просто скрывались. Счётчики считают всех, поиск сужает только список
карточек справа; об этом написано сноской под панелью.

## Отделы со стажировкой

У отдела в справочнике есть флажок «Стажировка». Он отвязан от названия
отдела: переименование ничего не сломает, а угадывать по словам «контроль»
или «бронирование» система не пытается — флажок ставится руками один раз.

Для такого отдела оффер не собирается: блок полей оффера в форме создания
скрывается, в карточке вместо кнопки «Оффер» — «Сообщения», строки о статусе
оффера нет. После создания доступа открывается панель с двумя сообщениями для
телеграма или чата hh.ru:

1. приглашение на стажировку с вопросом о готовности;
2. детали выхода — дата, время — и доступы на страницу вместо письма.

Второе сообщение несёт одноразовый пароль, поэтому при повторном открытии
панели он перевыпускается, как и в письме-приглашении. «Отметить
отправленным» пишет в тот же `sentAt`, что и письмо, — статусы и фильтры в
списке доступов продолжают работать без отдельной ветки.

## Правила документов

Обязательные (по ним считается полнота пакета): паспорт, СНИЛС, военный билет
(только для мужчин), трудовая книжка, ИНН. Диплом, 2-НДФЛ и ответ про карту
Альфа-Банка на полноту **не влияют**.

### Документ, которого ещё нет

У новичка на первой работе трудовой книжки может не быть. Документ при этом
**остаётся обязательным**: он не уходит в необязательные и не пропадает из
знаменателя счётчика — просто под ним появляется вопрос «Оформляешь впервые?»
с ответом «Да, впервые». Ответ закрывает пункт (приносить нечего — оформим в
первый день), пишется в `firstTime[<ключ>]` и заодно ставит `progress[<ключ>]`.
Пока ответ стоит, отметку руками не снять (`aria-disabled` на пункте и проверка
в `toggleItem`), иначе счётчик и ответ разъехались бы. Повторный клик снимает
и ответ, и отметку.

В панели HR это видно в окне «чего не хватает» строкой «Оформляем впервые
(приносить нечего): …» — HR понимает, почему пункт закрыт без документа.

Флаг живёт не в вёрстке, а в списке документов: в редакторе «Страница
сотрудника» у обязательного документа есть галочка «Может оформляться
впервые» (`first` в `config/page`, атрибут `data-first="1"`). Подстрока
собирается из DOM после каждой пересборки списка, поэтому переживает правки
HR — как и «только для мужчин».

## Пароли

В базе хранится только SHA-256 с индивидуальной солью — восстановить пароль нельзя,
можно выпустить новый. Проверка идёт в браузере: для прототипа этого достаточно,
для боевой версии нужен сервер (bcrypt/argon2 и проверка на бэкенде) или SSO.

## Письмо-приглашение

Собирается в панели HR после выдачи доступа. Табличная вёрстка с инлайн-стилями и
дублирующими атрибутами `bgcolor` — переживает чистку HTML в веб-почте. Кнопка
«Скопировать письмо» кладёт в буфер оба формата (`text/html` и `text/plain`), поэтому
в Яндекс.Почту или Gmail вставляется с оформлением.

Цвета по брендбуку: Pantone Hexachrome Green C `#009634`, Pantone 447 C `#484E41`,
белый. Правило брендбука соблюдено: оливковый нигде не касается зелёного.

Кегли в обоих письмах одни и те же: 16px — весь текст, 20px — заголовок и
доступы, 13px — подписи и служебные строки. Больше ничего.

## Что это ещё не умеет

- Настоящей авторизации нет: код и пароль проверяются в браузере, страница доступна
  только внутри организации в Claude.
- Письмо отправляется вручную — копированием из панели. Автоотправка требует
  почтового коннектора для `hr@iway.ru` или своего бэкенда.
- Справочник отделов заполняется руками в панели; руководитель и старший
  подтягиваются в письмо и на страницу сотрудника только после этого.
