# Портал новых сотрудников i'way

Прототип пребординг-портала: HR выдаёт новичку персональный доступ, новичок видит
страницу со своей командой, документами и планом адаптации, HR следит за готовностью
пакета документов.

**Опубликованная версия:** https://claude.ai/artifact/JY6fX2C2VFecFyGJrLYLH9

Страница — один самодостаточный HTML-файл: шрифты, логотип и вся логика вшиты внутрь,
внешних запросов нет. Данные (сотрудники, администраторы, справочник отделов) живут
в общей базе артефакта, а не в файле.

---

## Структура

```
src/iway-welcome.html   вся страница: вёрстка, стили, логика, шрифты и логотип в base64
assets/                 исходные PNG логотипа (из них собран base64 в странице)
tools/build_logo.py     пересборка логотипа в фирменные цвета
tools/build_fonts.py    сабсет Fedra Sans Pro → woff2 → base64
tests/                  автотесты на Playwright + эмулятор базы артефакта
```

## Три экрана в одном файле

| Экран | Когда показывается |
|---|---|
| Вход | нет активной сессии; две вкладки — «Сотрудник» и «HR» |
| Панель HR | вход по почте и паролю администратора |
| Страница сотрудника | вход по логину/почте и паролю новичка |

В панели HR шесть вкладок, в порядке шапки: «Новый доступ» (открыта по
умолчанию), «Выданные доступы», «Администраторы», «Отделы», «Шаблоны»,
«Страница сотрудника». Имя администратора и «Выйти» стоят в правом верхнем
углу, вкладки — своей строкой под ними (`.tabs{flex-basis:100%}`, чтобы имя не
уезжало под вкладки, когда их становится много). Порядок вкладок и положение
имени проверяются в `flow13.py`. Панель письма-приглашения лежит под
вкладками — её открывают и после создания доступа, и кнопкой «Письмо» из
карточки в списке. Смена вкладки её не закрывает: в ней одноразовый пароль,
который иначе пришлось бы перевыпускать из-за случайного клика. Закрывается
кнопкой «Закрыть», и пока письмо не отмечено отправленным, она переспрашивает.

Маршрутизация — по хешу: `#admin`, `#code=IW-XXXX` (подставляет логин на экране входа),
`#exit`. Якоря разделов (`#docs`, `#team`, …) маршрут не переключают.

## Палитра

Страница и письмо живут на одной палитре — брендбучной. Раньше страница была
на синем `#0055A4` с лаймовым героем, чего нет ни в брендбуке, ни в логотипе
(в логотипе только `#484E41` и `#009634`), ни в письме.

| Роль | Значение |
|---|---|
| Акцент-графика: чекбоксы, полосы прогресса, фокус | Pantone Hexachrome Green C `#009634` |
| Всё, что несёт текст: кнопки, ссылки, подписи, полоса «Жизнь» | `#007026` |
| Заголовки | `#3A3F34` |
| Основной текст | `#5A6055` |
| Приглушённый текст | `#63715F` |
| Фон плашек и героя | `#E4F1E8`, страницы — `#F3F5F1` / белый |

Затемнённый `#007026` нужен там, где на цвете лежит текст: белая подпись на
чистом Green C даёт 3.88:1 и не проходит AA. На `#007026` — 6.28:1. Сам Green C
остался в графике, где контраст к тексту не предъявляется.

Все текстовые пары проверены на AA (минимум в наборе — 4.72:1). Токены
`--blue*` и `--avo` сохранили имена от прежней синей версии; значения в них
брендовые, переименование не делали, чтобы не раздувать правку.

## Данные

Коллекции в базе артефакта:

```
admins/<email>          { email, name, role, salt, hash, createdAt }
employees/<code>        { code, login, lastName, firstName, gender,
                          dept, email, personalEmail, startDate, startTime,
                          salt, hash, demoPass?, progress, cardChoice,
                          createdAt, openedAt, sentAt, docsSentAt,
                          offer?, offerSentAt? }
config/departments      { list: [{ name, head, senior, chat, intern }] }
config/page             { sections: { <ключ раздела>: { hidden, title, lead,
                                                        items? } } }
config/templates        { tpl: { offer: { subject, title, body },
                                 intern: { first, second } } }
```

- `progress` — именованные ключи документов: `passport`, `snils`, `military`,
  `labor`, `inn`, `diploma`, `ndfl`, плюс `day0…day4` для плана первого дня.
- `cardChoice` — `have` / `need` (карта Альфа-Банка).
- `demoPass` — только у тестовых профилей: пароль зафиксирован и не перевыпускается.
- `sentAt` — когда HR отметил письмо отправленным; `docsSentAt` — когда сотрудник
  нажал «Отправить список в HR».

## Блоки страницы сотрудника

Вкладка «Страница сотрудника» в панели HR: у каждого раздела личной страницы
можно переписать заголовок и подзаголовок и выключить показ. Настройки общие
для всех сотрудников, лежат в `config/page`.

Ключи разделов совпадают с их якорями: `hero`, `team`, `about`, `docs`,
`plan`, `culture`, `faq`, `contacts`. Первый экран скрыть нельзя — у него
правится только подзаголовок.

Пустое поле означает «текст из вёрстки»: исходные строки снимаются со
страницы при первой отрисовке и подсказываются в поле как placeholder, так
что правку всегда можно откатить, стерев значение. Скрытый раздел исчезает
вместе со своей ссылкой в навигации.

Списки внутри разделов тоже правятся: документы (обязательные и нет), план
первого дня, первая неделя, 30/60/90, ценности, карточки «Жизни», вопросы и
контакты. Строку можно переписать, добавить или удалить. Список лежит в
`items` своего раздела; там, где списков несколько, у остальных свои ключи
(`extra` у необязательных документов, `week` и `months` у плана).
Пока HR его не трогал, `items` нет и строки берутся из вёрстки; после первой
правки список отвязывается, а кнопка «Вернуть исходные» его обнуляет. Пустая
строка на странице не показывается, но в редакторе сохраняется — чтобы
недописанная не пропадала.

У контакта три поля: подпись, значение и ссылка. Ссылка необязательна: без
неё значение выводится без перехода, с надписью «Уточняется». Если значение
похоже на почту, `mailto:` подставляется само. Подпись у ссылки берётся из её
схемы — `mailto:` даёт «Написать», `tel:` — «Позвонить», остальное «Открыть».
Пускаем только `http(s):`, `mailto:` и `tel:`: поле правит один человек, а
открывают ссылку все, поэтому чужая схема вроде `javascript:` отбрасывается
и строка показывается без перехода.

Текст HR попадает на страницу через `textContent`: разметка в поле не
исполняется, а выводится как есть.

Отметки сотрудника привязаны к ключу пункта, а не к его порядку: у документов
это `data-key` из вёрстки, у плана первого дня — `day0…day4`. Редактор переносит
ключ существующего пункта как есть, новым выдаёт свой. Поэтому переименование
или перестановка не сбивает уже поставленные галочки, а удаление пункта просто
перестаёт их читать. Признак «только для мужчин» — тот же `data-doc="mil"`,
теперь их может быть несколько.

Нумерация ценностей («Ценность 01») проставляется по порядку сама, первая
карточка «Жизни» всегда выделена цветом — чтобы список нельзя было привести
в несогласованный вид.

Скрытие «Документов» и «Адаптации» уносит чек-листы — сотрудник не сможет
отметить документы и отправить список, а счётчик готовности в шапке замрёт.
Это не запрещено, но в интерфейсе подписано.

## Оффер

Отправляется тем же способом, что приглашение: HR собирает письмо, копирует
его в свою почту и отмечает отправленным. Поля живут в `rec.offer`, отметка —
в `offerSentAt`.

Заполнить можно сразу в форме «Новый доступ» — тогда после создания карточки
панель оффера открывается вместе с панелью приглашения. Позже оффер
открывается кнопкой «Оффер» в карточке; правки в полях сохраняются сразу и
сразу видны в предпросмотре.

Порядок абзацев и формулировки задаёт шаблон (вкладка «Шаблоны»), а не код:
сплошной текст, без сведения условий в таблицы. `flow15.py` проверяет этот
порядок на исходном шаблоне отдельно.

Тема письма: `Оффер для Фамилия Имя на позицию «должность», i’way`. Она видна
в подсказке у кнопки «Тема» и проверяется тестом.

Переменные: должность, задачи (каждая строка — отдельный пункт), испытательный
срок, график, часы работы, руководитель, зарплата на испытательном и после,
дата ответа. Пустое поле просто не попадает в письмо: без должности нет абзаца
про должность, без срока ответа — строки про срок.

## Шаблоны писем

Вкладка «Шаблоны»: текст оффера (тема, заголовок, тело) и двух сообщений о
стажировке правятся как обычный текст. Значения из карточки подставляются по
именам в фигурных скобках, вёрстка письма от текста не зависит.

Подстановки оффера: `{имя}` `{фамилия}` `{должность}` `{задачи}`
`{испытательный срок}` `{график}` `{часы работы}`
`{зарплата на испытательном}` `{зарплата после}` `{руководитель}`
`{срок ответа}`.
Подстановки стажировки: `{имя}` `{фамилия}` `{дата выхода}` `{время выхода}`
`{ссылка}` `{логин}` `{пароль}`.

Правила разметки шаблона:

- абзацы разделяются пустой строкой;
- строка, начинающаяся с `- `, становится пунктом списка;
- **строка с пустой подстановкой выпадает целиком** — иначе в письме осталось
  бы «в должности «»» или «до  включительно»;
- `[кусок в квадратных скобках]` необязателен: с пустой подстановкой внутри
  исчезает только он, а строка остаётся. Так `Ждём вас {дата выхода}[ в
  {время выхода}].` не теряет дату, если время не указано;
- блок, от которого осталась одна ведущая строка на «:», не печатается —
  заголовок без списка смысла не имеет.

Значения подставляются выделенными (полужирный, цвет 447 C), многострочные
(задачи) — без выделения. Весь текст экранируется: теги из поля попадут в
письмо буквами, а не разметкой.

В поле сразу лежит текст, который уходит в письмо: его правят с места, а не
набирают заново поверх подсказки. Исходные тексты лежат в `TPL_DEFAULT` в коде;
в базу попадает только то, что HR действительно тронул, а очищенное поле снова
берёт текст из кода. Кнопка «Вернуть исходные» сбрасывает всё сразу и
переспрашивает. Правки лежат в `config/templates` и общие для
всех — как настройки страницы.

## Отделы со стажировкой

У отдела в справочнике есть флажок «Стажировка». Он отвязан от названия
отдела: переименование ничего не сломает, а угадывать по словам «контроль»
или «бронирование» система не пытается — флажок ставится руками один раз.

Для такого отдела оффер не собирается: блок полей оффера в форме создания
скрывается, в карточке вместо кнопки «Оффер» — «Сообщения», строки о статусе
оффера нет. После создания доступа открывается панель с двумя сообщениями для
телеграма или чата hh.ru:

1. приглашение на стажировку с вопросом о готовности;
2. детали выхода — дата, время — и доступы на страницу вместо письма.

Второе сообщение несёт одноразовый пароль, поэтому при повторном открытии
панели он перевыпускается, как и в письме-приглашении. «Отметить
отправленным» пишет в тот же `sentAt`, что и письмо, — статусы и фильтры в
списке доступов продолжают работать без отдельной ветки.

## Правила документов

Обязательные (по ним считается полнота пакета): паспорт, СНИЛС, военный билет
(только для мужчин), трудовая книжка, ИНН. Диплом, 2-НДФЛ и ответ про карту
Альфа-Банка на полноту **не влияют**.

## Пароли

В базе хранится только SHA-256 с индивидуальной солью — восстановить пароль нельзя,
можно выпустить новый. Проверка идёт в браузере: для прототипа этого достаточно,
для боевой версии нужен сервер (bcrypt/argon2 и проверка на бэкенде) или SSO.

## Письмо-приглашение

Собирается в панели HR после выдачи доступа. Табличная вёрстка с инлайн-стилями и
дублирующими атрибутами `bgcolor` — переживает чистку HTML в веб-почте. Кнопка
«Скопировать письмо» кладёт в буфер оба формата (`text/html` и `text/plain`), поэтому
в Яндекс.Почту или Gmail вставляется с оформлением.

Цвета по брендбуку: Pantone Hexachrome Green C `#009634`, Pantone 447 C `#484E41`,
белый. Правило брендбука соблюдено: оливковый нигде не касается зелёного.

Кегли в обоих письмах одни и те же: 16px — весь текст, 20px — заголовок и
доступы, 13px — подписи и служебные строки. Больше ничего.

## Тесты

```bash
cd tests
python3 flow6.py     # четыре способа входа + отказ на неверном пароле
python3 flow7.py     # диалоги вместо confirm/prompt, правка и удаление доступа
python3 flow11.py    # обязательные/необязательные документы, карта, отправка списка
```

| Файл | Что проверяет |
|---|---|
| `flow4.py` | сборка письма, личная почта в записи |
| `flow5.py` | копирование письма с вёрсткой, отметка «отправлено» |
| `flow6.py` | вход по логину, коду, почте; регистр и пробелы; мусорный ввод |
| `flow7.py` | системные окна заблокированы — работают свои диалоги |
| `flow8.py` | прогресс документов долетает в панель HR вживую |
| `flow9.py` | пол: военный билет только у мужчин; заявка на карту |
| `flow10.py` | карточки, фильтры по статусу, поиск, окно настроек |
| `flow11.py` | правила обязательных документов и кнопка «Отправить список» |
| `flow12.py` | навигация: на первом экране в герое, после — в шапке |
| `flow13.py` | вкладки панели HR: создание и список разделены, письмо общее |
| `flow14.py` | блоки страницы: текст, скрытие, все списки, ключи отметок, ссылки |
| `flow15.py` | оффер: поля при создании, письмо, отметка об отправке, правка |
| `flow16.py` | стажировка: флажок отдела, вместо оффера — сообщения для чата |
| `flow17.py` | шаблоны: правка текста, подстановки, скобки, возврат исходных |

`tests/mockdb.js` — эмулятор базы артефакта. Важно: он отдаёт снимки **замороженными**,
как настоящая платформа. Именно на этом ловится класс багов, когда правка записи
молча теряется.

Нужны `playwright` и Chromium:

```bash
pip install playwright pillow fonttools brotli
```

## Пересборка ассетов

```bash
python3 tools/build_logo.py <логотип.jpg> assets
python3 tools/build_fonts.py <каталог-с-otf>
```

Файлы Fedra Sans Pro в репозитории не лежат — шрифт лицензионный. Его сабсет уже
вшит в `src/iway-welcome.html`; скрипт нужен, только если понадобится пересобрать.

## Что это ещё не умеет

- Настоящей авторизации нет: код и пароль проверяются в браузере, страница доступна
  только внутри организации в Claude.
- Письмо отправляется вручную — копированием из панели. Автоотправка требует
  почтового коннектора для `hr@iway.ru` или своего бэкенда.
- Справочник отделов заполняется руками в панели; руководитель и старший
  подтягиваются в письмо и на страницу сотрудника только после этого.
