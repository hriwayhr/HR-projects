# Портал новых сотрудников i'way

Прототип пребординг-портала: HR выдаёт новичку персональный доступ, новичок видит
страницу со своей командой, документами и планом адаптации, HR следит за готовностью
пакета документов.

**Опубликованная версия:** https://claude.ai/artifact/JY6fX2C2VFecFyGJrLYLH9

Страница — один самодостаточный HTML-файл: шрифты, логотип и вся логика вшиты внутрь,
внешних запросов нет. Данные (сотрудники, администраторы, справочник отделов) живут
в общей базе артефакта, а не в файле.

---

## Структура

```
src/iway-welcome.html   вся страница: вёрстка, стили, логика, шрифты и логотип в base64
assets/                 исходные PNG логотипа (из них собран base64 в странице)
tools/build_logo.py     пересборка логотипа в фирменные цвета
tools/build_fonts.py    сабсет Fedra Sans Pro → woff2 → base64
tests/                  автотесты на Playwright + эмулятор базы артефакта
```

## Три экрана в одном файле

| Экран | Когда показывается |
|---|---|
| Вход | нет активной сессии; две вкладки — «Сотрудник» и «HR» |
| Панель HR | вход по почте и паролю администратора |
| Страница сотрудника | вход по логину/почте и паролю новичка |

В панели HR четыре вкладки: «Новый доступ» (открыта по умолчанию), «Выданные
доступы», «Отделы», «Администраторы». Панель письма-приглашения лежит под
вкладками — её открывают и после создания доступа, и кнопкой «Письмо» из
карточки в списке. Смена вкладки её не закрывает: в ней одноразовый пароль,
который иначе пришлось бы перевыпускать из-за случайного клика. Закрывается
кнопкой «Закрыть», и пока письмо не отмечено отправленным, она переспрашивает.

Маршрутизация — по хешу: `#admin`, `#code=IW-XXXX` (подставляет логин на экране входа),
`#exit`. Якоря разделов (`#docs`, `#team`, …) маршрут не переключают.

## Палитра

Страница и письмо живут на одной палитре — брендбучной. Раньше страница была
на синем `#0055A4` с лаймовым героем, чего нет ни в брендбуке, ни в логотипе
(в логотипе только `#484E41` и `#009634`), ни в письме.

| Роль | Значение |
|---|---|
| Акцент-графика: чекбоксы, полосы прогресса, фокус | Pantone Hexachrome Green C `#009634` |
| Всё, что несёт текст: кнопки, ссылки, подписи, полоса «Жизнь» | `#007026` |
| Заголовки | `#3A3F34` |
| Основной текст | `#5A6055` |
| Приглушённый текст | `#63715F` |
| Фон плашек и героя | `#E4F1E8`, страницы — `#F3F5F1` / белый |

Затемнённый `#007026` нужен там, где на цвете лежит текст: белая подпись на
чистом Green C даёт 3.88:1 и не проходит AA. На `#007026` — 6.28:1. Сам Green C
остался в графике, где контраст к тексту не предъявляется.

Все текстовые пары проверены на AA (минимум в наборе — 4.72:1). Токены
`--blue*` и `--avo` сохранили имена от прежней синей версии; значения в них
брендовые, переименование не делали, чтобы не раздувать правку.

## Данные

Коллекции в базе артефакта:

```
admins/<email>          { email, name, role, salt, hash, createdAt }
employees/<code>        { code, login, lastName, firstName, gender,
                          dept, email, personalEmail, startDate, startTime,
                          salt, hash, demoPass?, progress, cardChoice,
                          createdAt, openedAt, sentAt, docsSentAt }
config/departments      { list: [{ name, head, senior, chat }] }
```

- `progress` — именованные ключи документов: `passport`, `snils`, `military`,
  `labor`, `inn`, `diploma`, `ndfl`, плюс `day0…day4` для плана первого дня.
- `cardChoice` — `have` / `need` (карта Альфа-Банка).
- `demoPass` — только у тестовых профилей: пароль зафиксирован и не перевыпускается.
- `sentAt` — когда HR отметил письмо отправленным; `docsSentAt` — когда сотрудник
  нажал «Отправить список в HR».

## Правила документов

Обязательные (по ним считается полнота пакета): паспорт, СНИЛС, военный билет
(только для мужчин), трудовая книжка, ИНН. Диплом, 2-НДФЛ и ответ про карту
Альфа-Банка на полноту **не влияют**.

## Пароли

В базе хранится только SHA-256 с индивидуальной солью — восстановить пароль нельзя,
можно выпустить новый. Проверка идёт в браузере: для прототипа этого достаточно,
для боевой версии нужен сервер (bcrypt/argon2 и проверка на бэкенде) или SSO.

## Письмо-приглашение

Собирается в панели HR после выдачи доступа. Табличная вёрстка с инлайн-стилями и
дублирующими атрибутами `bgcolor` — переживает чистку HTML в веб-почте. Кнопка
«Скопировать письмо» кладёт в буфер оба формата (`text/html` и `text/plain`), поэтому
в Яндекс.Почту или Gmail вставляется с оформлением.

Цвета по брендбуку: Pantone Hexachrome Green C `#009634`, Pantone 447 C `#484E41`,
белый. Правило брендбука соблюдено: оливковый нигде не касается зелёного.

## Тесты

```bash
cd tests
python3 flow6.py     # четыре способа входа + отказ на неверном пароле
python3 flow7.py     # диалоги вместо confirm/prompt, правка и удаление доступа
python3 flow11.py    # обязательные/необязательные документы, карта, отправка списка
```

| Файл | Что проверяет |
|---|---|
| `flow4.py` | сборка письма, личная почта в записи |
| `flow5.py` | копирование письма с вёрсткой, отметка «отправлено» |
| `flow6.py` | вход по логину, коду, почте; регистр и пробелы; мусорный ввод |
| `flow7.py` | системные окна заблокированы — работают свои диалоги |
| `flow8.py` | прогресс документов долетает в панель HR вживую |
| `flow9.py` | пол: военный билет только у мужчин; заявка на карту |
| `flow10.py` | карточки, фильтры по статусу, поиск, окно настроек |
| `flow11.py` | правила обязательных документов и кнопка «Отправить список» |
| `flow12.py` | навигация: на первом экране в герое, после — в шапке |
| `flow13.py` | вкладки панели HR: создание и список разделены, письмо общее |

`tests/mockdb.js` — эмулятор базы артефакта. Важно: он отдаёт снимки **замороженными**,
как настоящая платформа. Именно на этом ловится класс багов, когда правка записи
молча теряется.

Нужны `playwright` и Chromium:

```bash
pip install playwright pillow fonttools brotli
```

## Пересборка ассетов

```bash
python3 tools/build_logo.py <логотип.jpg> assets
python3 tools/build_fonts.py <каталог-с-otf>
```

Файлы Fedra Sans Pro в репозитории не лежат — шрифт лицензионный. Его сабсет уже
вшит в `src/iway-welcome.html`; скрипт нужен, только если понадобится пересобрать.

## Что это ещё не умеет

- Настоящей авторизации нет: код и пароль проверяются в браузере, страница доступна
  только внутри организации в Claude.
- Письмо отправляется вручную — копированием из панели. Автоотправка требует
  почтового коннектора для `hr@iway.ru` или своего бэкенда.
- Справочник отделов заполняется руками в панели; руководитель и старший
  подтягиваются в письмо и на страницу сотрудника только после этого.
