# Слияние: корпоративный портал + HR-метрики

Документ для продолжения работы в чате «HR workspace с дашбордом метрик»
(ветка `claude/lucid-galileo-jpib8n`). Здесь — что уже сделано со стороны
пребординга, о чём договорились и что проверено в живых базах.
Дата сверки данных: 22.10.2026.

## Решение

Один проект «Корпоративный портал i'way» с уровнями доступа; **HR-метрики видят
только HR**. Портал собирается **на адресе артефакта метрик**
`https://claude.ai/artifact/LT73wVkVx9bYcwANYwPVt1`, потому что база у каждого
артефакта своя, а объёмы несимметричны:

| База | Документов | Что внутри |
|---|---|---|
| Пребординг `JY6fX2C2VFecFyGJrLYLH9` | 9 | `employees` 4, `admins` 2, `config/departments`, `config/page`, `config/templates` |
| Метрики `LT73wVkVx9bYcwANYwPVt1` | ~170 | `config/team`, `config/metrics`, `months` 78, `vacancies` 85, `vacations`, `rejections` |

Переносим 9 документов пребординга, а не 170 документов метрик: история метрик за
два года пополняется ежедневно, двигать её рискованнее. На прежнем адресе
пребординга остаётся заглушка с переадресацией (в том числе `#code=…`).

**Ссылки новичкам ещё не рассылались**: у всех реальных записей `sentAt` пуст
(IW-79KN, IW-UTKL, IW-XWUA), заполнен только у демо-профиля IW-TEST. Смена адреса
никому не ломает вход.

## Что уже готово на стороне пребординга

Ветка `claude/jolly-pasteur-pn79ou`, артефакт `JY6fX2C2VFecFyGJrLYLH9` версия 61.

- `src/iway-welcome.html` → **`src/iway-portal.html`**, заголовок страницы
  «Корпоративный портал i'way».
- **Один вход на всех** вместо вкладок «Сотрудник / HR»: в поле принимается логин,
  код доступа или рабочая почта. Сначала ищем HR по почте в `admins/<почта>`,
  потом новичка — по логину, рабочей почте или коду (`asEmployee`).
- **Экран «Разделы»** (`#viewHome`, `renderHome`, таблица `SECTIONS`) — карточки
  по уровню доступа. Сейчас два раздела: «Доступы и адаптация» (панель HR) и
  «HR-метрики» (пока внешняя ссылка на артефакт метрик).
- **Уровни доступа**: новичок видит только свою страницу (`#home` возвращает его в
  кабинет, `#admin` — на вход с пояснением «раздел только для HR»); HR видит оба
  раздела. Роль берётся из сессии (`roleOf`), а не из имён людей.
- `src/iway-metrics.html` — снимок артефакта метрик, взятый под версионный
  контроль до слияния (на ветке метрик актуальнее: `src/hr-metrics.html`).
- Тесты flow4–flow24 (21 шт.) зелёные; `flow24.py` покрывает портал. Сиды считают
  даты относительно сегодня (`day(±n)`, `ru(n)`, `dmy(n)`) — жёстко зашитые даты
  протухали и роняли пять тестов не из-за кода.

## Что сходится само собой

- **Схема паролей одна и та же**: `SHA-256(salt + '::' + пароль)`, соль — 8 байт
  hex. Значит пароли переносятся как есть, без сброса.
- Палитра и шрифт общие (Fedra Sans Pro, Pantone Hexachrome Green `#009634`), при
  слиянии в один файл шрифты остаются в одном экземпляре — минус ~250 КБ.

## Что придётся развести руками

1. **Люди заведены дважды.** Юлия и Анна есть и в `admins/*` (пребординг), и в
   `config/team` (метрики) — с разными паролями. Нужен один реестр и один пароль
   на человека. Роли после слияния:
   | Роль | Откуда | Что открыто |
   |---|---|---|
   | Новичок | `employees/<код>` с паролем | своя страница адаптации |
   | Рекрутер | `config/team`, `recruiter` | метрики: свой день, сводка, вакансии, отпуск |
   | HR-админ | `admins/*` + `config/team.admin` | всё: пребординг, метрики целиком, настройки |
2. **Совпадают имена в CSS и DOM.** В обоих приложениях есть `.panel`, `.btn`,
   `.tab`, `.note`, `.hint`, `.actions`, `.wrap`, `.bar`, `.me`, `.sub`, а также
   id `#tabs`, `#me`, `#logout`, `#viewLogin`. Оба скрипта объявляют `$`, `esc`,
   `today`, `hashPw`, `checkPassword`, `randHex`, `session`. Модули нужно
   изолировать: CSS каждого раздела — под свой корневой класс (переменные темы
   переопределяются на нём, а не на `:root`), скрипт — в своей IIFE.
3. **У метрик есть серверные варианты.** `cloud/` (функция Яндекс Облака + YDB,
   права в `cloud/function/acl.js`), `server/`, `local/`. Уровни доступа портала
   должны ложиться на серверную проверку прав, а не только на интерфейс артефакта.
4. **README на ветке метрик устарел** — описывает старый пребординг до портала.

## Порядок работ

1. Свести ветки `claude/jolly-pasteur-pn79ou` (портал) и
   `claude/lucid-galileo-jpib8n` (метрики, облако, локальная версия).
2. Внести метрики в `src/iway-portal.html` отдельным модулем с изоляцией CSS и JS;
   собственный вход метрик убрать — его заменяет вход портала.
3. Единый реестр людей и три роли; права в `cloud/function/acl.js` привести к ним же.
4. Перенести 9 документов пребординга в базу артефакта метрик, сверить поштучно.
5. Опубликовать портал на `LT73wVkVx9bYcwANYwPVt1`; на `JY6fX2C2VFecFyGJrLYLH9`
   оставить заглушку с переадресацией, включая `#code=…`.
6. Тесты на оба модуля и на разграничение доступа; README переписать под портал.
